ЭТАП 15: ПРОФЕССИОНАЛЬНЫЙ СИСТЕМНЫЙ ТРЕЙ
ПРОЕКТ: Zapret Manager — десктопное приложение для управления

═══════════════════════════════════════════════════════════════════════

🎯 ЦЕЛЬ ЭТАПА

Создать полноценный системный трей (System Tray) с пятью
состояниями иконки, анимациями, контекстным меню с динамическими
пунктами, быстрыми действиями по кликам (левый / правый / средний),
нативными уведомлениями и настройками трея. Трей должен стать
основным способом управления приложением, когда окно свёрнуто:
пользователь видит текущий статус, может запустить/остановить
стратегию, переключиться на VPN, открыть логи или настройки — всё
без разворачивания окна.

После этого этапа пользователь сможет:
• Видеть в трее иконку, отражающую текущее состояние
(idle / connecting / connected / vpn / error)
• Видеть анимацию иконки при подключении (пульсация)
• Открыть контекстное меню правым кликом:

Текущий статус (заголовок, не кликабельный)

Запустить последнюю стратегию / Остановить

Переключиться на VPN / Отключить VPN

Открыть Dashboard / Стратегии / Логи / Настройки

Проверить обновления

Выход
• Левый клик — показать/скрыть окно
• Средний клик — быстрый запуск последней стратегии
• Двойной клик — открыть Dashboard
• Получать уведомления Windows при:

Запуске стратегии (опционально)

Остановке стратегии (опционально)

Ошибке

Доступном обновлении

Подключении/отключении VPN
• Настроить поведение трея в Settings → Общие:

Сворачивать в трей при закрытии (уже есть)

Запускать свёрнутым (уже есть)

Показывать уведомления (уже есть)

Анимировать иконку при подключении (новое)

Это критичный этап для UX. Трей — это то, что пользователь видит
90% времени, когда приложение работает в фоне. Он должен быть
информативным, отзывчивым и красивым.

🏗️ ЧАСТЬ 1: АРХИТЕКТУРНЫЕ РЕШЕНИЯ (обосновать перед реализацией)
═══════════════════════════════════════════════════════════════════════

【 РЕШЕНИЕ 1: Tauri 2 TrayIcon API с кастомными иконками 】

ОБОСНУЙ:
• Tauri 2 предоставляет tauri::tray::TrayIconBuilder —
кросс-платформенный API для системного трея
• Поддерживает: иконку, tooltip, контекстное меню,
обработку кликов (left, right, double, middle)
• Иконки можно менять динамически через tray.set_icon()
• Меню можно перестраивать через tray.set_menu()
• Работает на Windows 10/11 без дополнительных зависимостей

ПОЧЕМУ НЕ WINDOWS API НАПРЯМУЮ (Shell_NotifyIcon):
• Сложнее, больше кода
• Tauri уже абстрагирует это
• Потеряется кросс-платформенность (macOS/Linux)

ПОЧЕМУ НЕ TAURI PLUGIN:
• В Tauri 2 трей встроен в ядро, плагин не нужен

【 РЕШЕНИЕ 2: 5 состояний иконки — статические PNG + анимация 】

ОБОСНУЙ:
• idle: серая иконка щита (неактивно)
• connecting: жёлтая иконка с точкой (подключение)
• connected: зелёная иконка щита (активно)
• vpn: голубая иконка замка (VPN)
• error: красная иконка с восклицательным знаком (ошибка)

Анимация:
• При переходе в connecting — быстрая смена 2–3 кадров
(пульсация) с интервалом 300ms
• При переходе в connected — плавное появление (fade in)
• Анимация останавливается через 3 секунды после
установления соединения

ПОЧЕМУ PNG, А НЕ SVG:
• Windows Tray API принимает только HICON (растровые)
• PNG 32x32 и 16x16 (для разных DPI)
• Tauri конвертирует PNG в HICON автоматически

ПОЧЕМУ НЕ ОДНА ИКОНКА С ЦВЕТОВЫМ ФИЛЬТРОМ:
• Цветовой фильтр через код — сложно, не всегда корректно
• 5 готовых PNG — проще, надёжнее
• Размер: 5 × 2 KB = 10 KB — незначительно

【 РЕШЕНИЕ 3: Контекстное меню — динамическое, перестраивается при изменении состояния 】

ОБОСНУЙ:
• Меню должно отражать текущее состояние:

Если стратегия запущена → пункт «Остановить»

Если не запущена → пункт «Запустить: Discord + YouTube»

Если VPN активен → «Отключить VPN»

Если VPN не активен → «Подключить VPN»
• Меню перестраивается при каждом изменении состояния
• Tauri позволяет tray.set_menu(Some(menu)) для обновления

ПОЧЕМУ НЕ СТАТИЧЕСКОЕ МЕНЮ:
• Пользователь не должен видеть неактивные пункты
• «Запустить», когда уже запущено — путает

ПОЧЕМУ НЕ ДВА МЕНЮ (одно для idle, одно для running):
• Сложнее поддерживать
• Динамическая сборка — гибче

【 РЕШЕНИЕ 4: Быстрые действия по кликам 】

ОБОСНУЙ:
• Левый клик — toggle окна (показать/скрыть).
Это стандарт для трей-приложений (Discord, Telegram).
• Правый клик — контекстное меню. Стандарт Windows.
• Средний клик — быстрый запуск/остановка последней
стратегии. Удобно для опытных пользователей.
• Двойной клик — открыть Dashboard.
Альтернатива для тех, кто привык к двойному клику.

ПОЧЕМУ НЕ ТОЛЬКО ПРАВЫЙ КЛИК:
• Левый клик — самый частый
• Двойной клик — интуитивно для открытия
• Средний клик — «power user» фича

【 РЕШЕНИЕ 5: Уведомления через tauri-plugin-notification 】

ОБОСНУЙ:
• Windows Toast Notifications — нативные, красивые
• Плагин уже подключён (Этап 1)
• Уведомления отправляются из Rust или из JS
• Настройка «Показывать уведомления» в Settings

ТИПЫ УВЕДОМЛЕНИЙ:
• Успех: «Стратегия запущена» (опционально, по умолчанию выкл)
• Ошибка: «Не удалось запустить стратегию»
• Обновление: «Доступна новая версия 1.9.6»
• VPN: «VPN подключён» / «VPN отключён»
• Предупреждение: «Возможна утечка IP»

ПОЧЕМУ НЕ КАСТОМНЫЕ ОКНА:
• Нативные уведомления не требуют фокуса
• Работают, когда окно свёрнуто
• Стандарт Windows

【 РЕШЕНИЕ 6: Синхронизация состояния трея с основным приложением 】

ОБОСНУЙ:
• Трей — часть Rust-процесса, но состояние живёт в
frontend (Zustand)
• Rust должен знать о состоянии, чтобы менять иконку и меню
• Решение: Rust-команда update_tray_state(state: TrayState),
которую вызывает frontend при каждом изменении
• Или: Rust сам отслеживает состояние через events от
strategy runner / VPN

РЕКОМЕНДАЦИЯ: frontend вызывает update_tray_state при
изменении:
• strategy status (idle → running → error)
• VPN status (disconnected → connected)
• available update (есть/нет)

ПОЧЕМУ НЕ RUST САМ ОТСЛЕЖИВАЕТ:
• Дублирование логики
• Frontend уже имеет все сторы
• Проще синхронизировать из одного места

【 РЕШЕНИЕ 7: Анимация иконки через таймер в Rust 】

ОБОСНУЙ:
• При переходе в connecting — Rust запускает tokio-задачу,
которая каждые 300ms меняет иконку между 2–3 кадрами
• Через 3 секунды (или при переходе в connected/error) —
задача останавливается
• Не блокирует UI, не грузит CPU

ПОЧЕМУ НЕ CSS-АНИМАЦИЯ:
• Tray icon — системный ресурс, не DOM
• Анимация только через смену иконки

ПОЧЕМУ НЕ GIF:
• Windows Tray не поддерживает GIF
• Только статические HICON

【 РЕШЕНИЕ 8: Настройки трея в Settings → Общие 】

ОБОСНУЙ:
• Добавить в GeneralSection:

Toggle «Анимировать иконку при подключении»

Toggle «Показывать уведомления о запуске»

Toggle «Показывать уведомления об остановке»
• Сохраняются в settings.general
• Применяются мгновенно

ПОЧЕМУ В SETTINGS:
• Пользователь должен контролировать поведение
• Некоторые не любят анимации/уведомления

【 РЕШЕНИЕ 9: Обработка закрытия окна → сворачивание в трей 】

ОБОСНУЙ:
• Уже реализовано на Этапе 2 через on_window_event
• На этом этапе — убедиться, что работает корректно:

Если minimizeToTray=true → окно скрывается, трей остаётся

Если false → приложение закрывается полностью
• При закрытии через трей → полное завершение

ПОЧЕМУ НЕ ВСЕГДА СВОРАЧИВАТЬ:
• Пользователь должен иметь выбор
• Некоторые хотят полного закрытия

【 РЕШЕНИЕ 10: Иконки трея — отдельные от иконки приложения 】

ОБОСНУЙ:
• Иконка приложения (в окне, в установщике) — большая, цветная
• Иконка трея — маленькая (16x16 / 32x32), монохромная или
минималистичная
• Отдельные файлы в src-tauri/icons/tray/
• Tauri автоматически выбирает размер по DPI

ПОЧЕМУ ОТДЕЛЬНЫЕ:
• Маленькая иконка с деталями выглядит «грязно»
• Упрощённая иконка читается лучше

⚠️ ЧАСТЬ 5: ЧТО МОЖЕТ СЛОМАТЬСЯ (гипотезы)
═══════════════════════════════════════════════════════════════════════

ГИПОТЕЗА 1: Иконки не загружаются
ПРИЧИНА: неправильный путь или формат PNG.
ЧТО ПРОВЕРИТЬ: Image::from_path возвращает Ok.
Пути относительно src-tauri/icons/tray/.

ГИПОТЕЗА 2: Меню не перестраивается
ПРИЧИНА: set_menu не вызывается или старый Menu не
удаляется.
ЧТО ПРОВЕРИТЬ: tray.set_menu(Some(new_menu)) вызывается
при каждом update_tray_state.

ГИПОТЕЗА 3: События трея не доходят до frontend
ПРИЧИНА: emit не вызывается или listener не подписан.
ЧТО ПРОВЕРИТЬ: app.emit("tray-run-strategy", ()) и
listen("tray-run-strategy", ...) в useTray.

ГИПОТЕЗА 4: Анимация не останавливается
ПРИЧИНА: tokio-задача не прерывается.
ЧТО ПРОВЕРИТЬ: stop_icon_animation вызывается при
переходе в connected/error.

ГИПОТЕЗА 5: Уведомления не приходят
ПРИЧИНА: разрешение notification не в capabilities.
ЧТО ПРОВЕРИТЬ: capabilities/default.json содержит
"notification:default".

ГИПОТЕЗА 6: Окно не скрывается по левому клику
ПРИЧИНА: window.hide() не вызывается.
ЧТО ПРОВЕРИТЬ: в handle_tray_click вызывается
app.get_webview_window("main").hide() / show().

ГИПОТЕЗА 7: Throttle не работает
ПРИЧИНА: useRef не сохраняет последнее время.
ЧТО ПРОВЕРИТЬ: update_tray_state не вызывается чаще
чем раз в 200ms.

ГИПОТЕЗА 8: Меню не закрывается после клика
ПРИЧИНА: Tauri должен закрывать автоматически.
ЧТО ПРОВЕРИТЬ: если не закрывается — вызвать
menu.popup() с правильными параметрами.
