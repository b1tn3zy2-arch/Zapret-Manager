🎯 ЦЕЛЬ ЭТАПА

Превратить базовую Settings (с Этапа 8, где была только секция
Outlast Trials) в полноценную страницу настроек с 8 рабочими
секциями: Общие, Внешний вид, Стратегии, Outlast Trials, VPN,
Обновления, Продвинутые, О приложении. Все настройки — рабочие
(не заглушки), сохраняются в config.json + localStorage,
поддерживают импорт/экспорт, сброс к дефолтным.

После этого этапа пользователь сможет:
  • Открыть Settings и увидеть 8 секций в виде аккордеона или
    боковой навигации
  • Изменить любую настройку → она мгновенно применяется и
    сохраняется
  • Экспортировать все настройки в JSON-файл
  • Импортировать настройки из файла (перенос на другой ПК)
  • Сбросить отдельную секцию или всё к дефолтным
  • Видеть информацию о версии, сборке, лицензиях
  • Открыть папки (config, logs, strategies) в проводнике
  • Проверить целостность конфигов

Settings — это «мозг» приложения. Здесь пользователь настраивает
всё под себя. Если настройка не работает или не сохраняется —
это критический баг. Поэтому здесь НЕЛЬЗЯ оставлять заглушки.

【 РЕШЕНИЕ 1: Layout — боковая навигация по секциям (не аккордеон) 】

ОБОСНУЙ:
  • 8 секций — многовато для аккордеона (много скролла)
  • Боковая навигация слева (внутри страницы) + контент справа
  • Навигация — sticky, при скролле контента остаётся на месте
  • Активная секция подсвечена
  • Клик → плавный скролл к секции (или мгновенный переход)
  • На мобильных — превращается в горизонтальный скролл табов

ПОЧЕМУ НЕ АККОРДЕОН:
  • При 8 секциях — длинная простыня
  • Пользователь не видит структуру
  • Плохой UX

ПОЧЕМУ НЕ ОТДЕЛЬНЫЕ СТРАНИЦЫ ДЛЯ КАЖДОЙ СЕКЦИИ:
  • Избыточно для десктоп-приложения
  • Пользователь хочет видеть всё в одном месте
  • Сложнее навигация

ПОЧЕМУ НЕ ВЕРХНИЕ ТАБЫ:
  • 8 табов — тесно
  • Нет места для длинных названий

【 РЕШЕНИЕ 3: Сохранение — debounce 500ms в файл + мгновенно в localStorage 】

ОБОСНУЙ:
  • localStorage — мгновенно (для UI-состояния)
  • config.json в %APPDATA% — debounce 500ms (для надёжности)
  • При старте: файл → localStorage (файл приоритетнее)
  • Это уже реализовано на Этапе 4 (useSettingsSync)
  • На Этапе 13 — используем существующий механизм

ПОЧЕМУ DEBOUNCE:
  • Пользователь двигает слайдер → 100 изменений в секунду
  • Без debounce — 100 записей в файл
  • С debounce — 1 запись после остановки

ПОЧЕМУ НЕ ТОЛЬКО ФАЙЛ:
  • Файл — медленнее
  • localStorage — мгновенно
  • Комбинация даёт лучший UX

【 РЕШЕНИЕ 4: Индикатор несохранённых изменений ]

ОБОСНУЙ:
  • Если изменения ещё не записаны в файл (в течение 500ms) —
    показать индикатор «Сохранение...» в углу страницы
  • После записи — «Сохранено» (исчезает через 1 сек)
  • Даёт пользователю уверенность, что настройки сохранены

ПОЧЕМУ ВАЖНО:
  • Пользователь не уверен, что настройки применятся
  • Стандарт для современных SaaS

【 РЕШЕНИЕ 5: Импорт/Экспорт настроек через JSON-файл ]

ОБОСНУЙ:

  • Импорт: dialog.open → прочитать JSON → валидировать через
    zod → применить (merge с дефолтными)
  • Версия схемы в файле (version: 1) — для будущих миграций
  • Экспорт НЕ включает: lastStrategyId, lastCheckAt,

ПОЧЕМУ ЭКСПОРТ:
  • Перенос на другой ПК

ПОЧЕМУ ZOD:

  • Уже в зависимостях (Этап 1)
