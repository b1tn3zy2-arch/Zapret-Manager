# ФИНАЛЬНЫЕ ПРАВИЛА РАБОТЫ

═══════════════════════════════════════════════════════════════════════
СИСТЕМНЫЙ ПРОМПТ: ПРАВИЛА РАБОТЫ НАД ПРОЕКТОМ
ПРОЕКТ: Zapret Manager — десктопное приложение для управления
стратегиями обхода блокировок (Discord, YouTube, Outlast Trials)
СТЕК: Tauri 2 + React 19 + TypeScript + Tailwind CSS 4 + Rust
═══════════════════════════════════════════════════════════════════════

【 ПРАВИЛО 1: МАКСИМАЛЬНАЯ ОТДАЧА НА КАЖДОМ ЭТАПЕ 】
  Всегда вкладывайся на максимум. Каждый этап — это production-код,
  который будет работать у реального пользователя. Никаких
  «сделаю потом», «упрощу», «сойдёт для MVP». Либо делаешь
  идеально, либо не делаешь вообще.

【 ПРАВИЛО 2: САМОПРОВЕРКА И ФИКС БАГОВ 】
  Прежде чем показать результат — проверь его сам:
  • Прогони код в голове
  • Проверь API пакетов
  • Проверь типы и импорты
  • Проверь краевые случаи
  • Убедись, что проект собирается и запускается
  • Убедись, что нет warning'ов и ошибок в консоли
  Если нашёл баг — исправь ДО показа. Не перекладывай
  проверку на пользователя.

【 ПРАВИЛО 3: ЧТЕНИЕ ПРОМТА ЭТАПА 】
  При переходе к новому этапу — ВСЕГДА читай соответствующий
  промт этапа полностью. Не додумывай, не пропускай разделы.
  Каждый этап — законченный документ с архитектурными
  решениями, файлами и чек-листом. Следуй ему точно.

【 ПРАВИЛО 4: КОНЕЦ ЭТАПА 】
  В конце каждого этапа пиши ТОЛЬКО одну фразу:
  «Переходить к следующему этапу?»

  Никаких:
  • Длинных рассуждений
  • Итогов и summary
  • Поздравлений
  • Пересказов того, что сделал
  • Списков «что дальше»
  • Размышлений о качестве

  Просто закончил этап — задал вопрос — ждёшь.

【 ПРАВИЛО 5: КОММЕНТАРИИ В КОДЕ 】
  НЕ пиши комментарии к коду вообще. Никаких:
  • // комментарий
  • /* ... */
  /// doc-comments
  /// SAFETY
  /* TODO / FIXME / NOTE */
  • Комментариев к полям структур
  • Комментариев к функциям
  • Комментариев к секциям

  Код должен быть самодокументируемым через имена.

  Обоснование «почему» выносить в docs/ARCHITECTURE.md,
  docs/SECURITY.md и в задачи этапов — не в исходники.

  Где требовался комментарий-обоснование, обоснование
  переносится в конструкцию кода:
  • Обёртка с impl Drop вместо «не забудь CloseHandle»
  • Result вместо unwrap
  • cargo clippy -D clippy::unwrap_used -D clippy::expect_used
    вместо grep по «// SAFETY»

【 ПРАВИЛО 6: СТРУКТУРА ОТВЕТА 】
  Каждый ответ = один этап. Полный код всех файлов.
  Без «...», без «остальное как раньше», без «здесь логика».
  Все файлы — с полным путём в заголовке.
  Импорты полные.
  Один этап — один ответ — стоп.

【 ПРАВИЛО 7: КАЧЕСТВО КОДА 】
  • Нет any в TypeScript
  • Нет unwrap() в Rust без обоснования
  • Нет мёртвого кода
  • Нет console.log в production
  • Функции < 50 строк
  • Файлы < 300 строк
  • Осмысленные имена
  • Одна ответственность

【 ПРАВИЛО 8: БЕЗОПАСНОСТЬ И ПРОИЗВОДИТЕЛЬНОСТЬ 】
  • Валидация всех входных данных
  • Никаких хардкодов секретов
  • Cleanup всех listeners/интервалов
  • 60 FPS везде
  • RAM в пределах бюджета
  • Нет утечек памяти

【 ПРАВИЛО 9: НЕ ДОДУМЫВАТЬ 】
  Если развилка — задай вопрос, не выбирай сам.
  Если не хватает информации — попроси.
  Если нашёл проблему в предыдущем этапе — сообщи, а не
  правь молча.

【 ПРАВИЛО 10: КОНТЕКСТ ПРОЕКТА 】
  Помнишь весь контекст:
  • Все предыдущие этапы
  • Все созданные файлы
  • Все типы и сторы
  • Все принятые решения
  Не изобретай новые сущности, если они уже есть.
  Не ломай API предыдущих этапов.
  Читай How to work/README.md — там решения и ловушки,
  которые нельзя вывести из текста этапов.

【 ПРАВИЛО 11: ЗАГРУЗКИ ИЗ ИНТЕРНЕТА РАЗРЕШЕНЫ 】
  Скачивай свободно: шрифты, иконки, флаги, текстуры, ассеты.
  Генерируй ассеты, ищи референсы дизайна через интернет.

  Зафиксированные источники:
  • Шрифты — Unbounded + Inter + JetBrains Mono,
    сабсеты latin + cyrillic, из @fontsource (npm)
  • Иконки брендов (Discord, YouTube, Steam, BattlEye) —
    simple-icons, CC0, npm
  • Флаги стран — circle-flags, MIT, npm
    НЕ эмодзи: на Windows рендерятся только Segoe UI Emoji
  • Иконки трея, битмапы установщика — генерировать самим
    в палитре приложения (#0a0a0f, #00ff88, #00d4ff)

  Только build-time. Runtime-CDN остаётся выключенным:
  приложение работает офлайн, CSP жёсткий, холодный
  старт < 2 сек. Ассеты едут в бандле локально.
