## Найденный дефект и исправление

**Дефект:** релизная сборка искала встроенные ресурсы по пути машины сборки —
`PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("resources")` был безусловным кандидатом
в `resource_roots()`. На машине без исходников путь не существует, поэтому первый запуск
не распаковывал стратегии, а `strategiesFolder` в настройках указывал на произвольный каталог.

**Как проявлялось:** на текущей машине (где исходники есть) приложение молча подставило
корень репозитория как папку стратегий — то есть поведение зависело от наличия исходного кода
на пользовательской машине.

**Исправление:** `src-tauri/src/commands/resources_fs.rs` — сборка кандидатов вынесена в
чистую функцию `build_resource_roots(resource_dir, exe_path, allow_manifest_dir)`, а путь
`CARGO_MANIFEST_DIR` добавляется только при `cfg!(debug_assertions)`. В релизной сборке
остаются только `resource_dir` и каталог рядом с исполняемым файлом.

**Проверка после исправления:** чистое удаление данных, повторная установка и запуск —
ресурсы распакованы в `%APPDATA%\com.zapretmanager.app\strategies` (23 стратегии),
приложение работает стабильно, удаление чистое.

## Второй дефект: portable-архив без ресурсов

**Дефект:** `scripts/release-artifacts.mjs` упаковывал в portable ZIP только
`zapret-manager.exe`. Без каталога `resources/` рядом с exe приложение не находит встроенные
стратегии: `%APPDATA%\com.zapretmanager.app\strategies` остаётся пустым, а первый запуск
показывает состояние «папка не выбрана».

**Исправление:** portable теперь содержит `zapret-manager.exe`, `resources/` и `icons/`
(69 файлов, 16.2 MB). Скрипт падает, если каталог `resources` отсутствует в сборке.

**Проверка:** `node scripts/verify-portable.mjs release/ZapretManager_0.1.0_x64_portable.zip`
распаковывает архив во временный каталог, запускает приложение, ждёт 18 секунд и проверяет,
что процесс жив и распаковано 23 стратегии.

## Не проверено на этой машине

- Установка на чистой Windows VM без Visual Studio Build Tools и без Rust.
- Поведение при обновлении с 0.0.9 (требует предыдущего релиза).
- Работа автообновления после публикации (нужен удалённый репозиторий).
- Проверка кода подписи (сертификата нет, сборка неподписанная — SmartScreen предупредит).
- Визуальная проверка иконки трея и нативных уведомлений (нужен человек за экраном).
